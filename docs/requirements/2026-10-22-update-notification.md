# 起動時に新しい版を知らせ、通知から更新できるようにする（Windows・Linux）

- Issue: なし
- 作成者: notelm
- ステータス: 承認済み
- 日付: 2026-10-22

## 問題

Windows の MSI、Linux の deb または tarball で orzma を入れた利用者は、新しい版が出たかどうかを知るために、自分で GitHub Releases を見に行かなければならない。作成者の言葉では「ユーザーがバージョン更新があるかを定期的にGithub Releasesを確認しないといけない」。

今の orzma は、新しい版が出ても何も知らせない。新しい版に気づいた利用者は、入れ方ごとに手で入れ直している。Windows では新しい MSI を実行し、Linux では新しい deb を `sudo apt install` で入れるか、新しい tarball を展開してインストーラーを実行し直す。deb は apt のリポジトリから配っていないので、apt が新しい版を拾うこともない。

## 求める解決

- R1: Windows または Linux で起動時の更新確認がオンのとき、起動した orzma より新しい版が GitHub Releases にあれば、orzma は新しい版があることを知らせる通知をウィンドウの中に表示する。
- R2: 通知でリリースページを開く操作を選ぶと、新しい版のリリースページが開く。
- R3: 通知には、選ぶと orzma が再起動することがラベルから分かる更新の操作（たとえば「再起動して更新」）がある。
- R4: 管理者権限が要らない入れ方で更新の操作を選ぶと、確認を求められることなく、新しい版の orzma が起動し直す。
- R5: 管理者権限が要る入れ方（Linux の deb、Windows で全ユーザー向けに入れた場合）で更新の操作を選ぶと、管理者の許可を求められ（Linux ではパスワードを入力する画面が表示され）、許可すると新しい版の orzma が起動し直す。
- R6: 利用者は起動時の更新確認をオフにでき、オフのあいだ orzma は起動時に新しい版を知らせない。
- R7: インストールした直後の orzma では、起動時の更新確認はオンになっている。

## 対象外

- macOS での通知と更新。Apple の署名と公証を済ませた後に、別の変更として扱う。
- 更新のための再起動の前後で、ペインで動いていたシェルやプログラムを引き継ぐこと。更新の操作を選ぶと、それらは orzma と一緒に終了する。

## 検討した代替案

- 利用者が GitHub の Watch で Releases だけを購読し、新しいリリースの通知を受け取る（提案: AI）— 作成者は、orzma 自身が起動時に新しい版を確認する仕組みを求めた。
- macOS では Homebrew（`brew upgrade`）に更新を任せる（提案: 作成者）— 作成者は、Windows に合わせて macOS にも同じ通知を入れたいとした。そのうえで macOS は、署名と公証の後に回した。
- Linux では通知から更新はせず、VS Code と同じく更新をパッケージの仕組みに任せる（提案: AI）— orzma の deb は apt のリポジトリから配っておらず、作成者は Linux でも通知から更新までできるようにしたいとした。
- 更新の操作を選ぶ前に、ペインのプログラムが終了することを利用者に知らせる（提案: AI）— 作成者は、再起動することがラベルで分かれば不要とした。

## 未決事項

- 起動時の更新確認が、SignPath Foundation の規約にある「利用者のデータを集めて、利用者が指定していない宛先に送る」機能に当たるか。当たる場合、規約はプライバシーポリシーをインストール時に表示することと、インストール時に無効にできる選択肢を求めている。（承認を妨げる: いいえ）
- 利用者は、どこで起動時の更新確認をオフにするか。（承認を妨げる: いいえ）
- orzma が終了してから新しい版が起動するまでのあいだ、利用者には何が見えるか。（承認を妨げる: いいえ）
- 新しい版のダウンロードや入れ替えに失敗したとき、利用者には何が見えるか。（承認を妨げる: いいえ）
- 通知を閉じた、またはどちらの操作も選ばなかった場合、同じ版の通知が次に表示されるのはいつか。（承認を妨げる: いいえ）
