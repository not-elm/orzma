# 全角文字・結合文字のセル表現

記録日: 2026-09-11 / 対象リビジョン: `90ce073e`

`Screen::print` の上にあった `// TODO:` をここに移した。コードからは削除済み。

## 1. 現状

`Screen::print`（`crates/orzma_vt/src/screen.rs:154`）は、どの文字も 1 セルに書いてカーソルを 1 カラム進める。
表示幅を見ていないので、表示幅 2 の全角文字も表示幅 0 の結合文字も同じ扱いになる。
doc comment には前提条件として「`c` は表示幅 1 の印字可能文字」と書いてある。

## 2. VT とレンダラーのずれ

VT とレンダラーでカラムの数え方が違う。

| 場所 | 数え方 |
|------|--------|
| `Run::cols` の doc（`crates/orzma_vt/src/screen/grid/run.rs:45`） | 「`text` 内の書記素クラスタの表示幅の合計」と約束している |
| `Row::to_runs`（`crates/orzma_vt/src/screen/grid/row.rs:52`） | 実際にはセル 1 つごとに `cols += 1` しており、中身はセル数になっている |
| レンダラーの `runs_to_cells`（`crates/bevy_orzma_tty_renderer/src/schema/grid.rs:342`） | 書記素ごとに表示幅ぶんカラムを進める（こちらが正しい形） |

### 全角文字: 後ろのセルが右にずれる

`あx` を出力した場合:

| | `あ` | `x` | カーソル |
|---|---|---|---|
| VT | カラム 0 | カラム 1 | カラム 2 |
| レンダラー | カラム 0〜1 | カラム 2 | — |

全角文字より後ろのセルは、VT 自身のカーソル位置より 1 カラム右に描かれる。
シェルなどのアプリは `あ` を幅 2 と数えるので、カーソル移動の計算も VT と合わなくなる。

### 結合文字: 後ろのセルが左にずれる

`e` + U+0301 + `x` を出力した場合、VT は `e` と `◌́` で 2 セル使う。
レンダラーは `é` を 1 つの書記素（幅 1）として描くので、`x` は VT の位置より 1 カラム左に描かれる。

## 3. 挿入モード（IRM）のずらし幅

`IRM` が有効なとき、`print` は文字を置く前に `insert_characters(1)` で行の残りを右へ 1 カラムずらす（`screen.rs:174`）。
xterm、alacritty、kitty、ghostty、foot、wezterm はどれも文字の表示幅ぶんずらす。
つまり全角文字なら 2 カラムずらす。

## 4. 直すべき箇所

3 か所は同じ前提に乗っているので、まとめて直す。

- **`Screen::print`**
  - 全角文字は、本体のセルと 2 カラム目を埋めるスペーサーセルで持つ。
  - 幅 0 の結合文字は、新しいセルを作らず直前のセルに合成する。
  - カーソルは表示幅ぶん進める。
  - doc comment の「表示幅 1」という前提条件を外す。
- **`Row::to_runs`**: `Run::cols` を表示幅の合計にする。スペーサーセルは `text` に入れない。`Run` の doc は「スペーサーは吸収されて `text` に現れない」とすでに書いている。
- **`IRM` のずらし幅**: `insert_characters(1)` を文字の表示幅ぶんに変える。

## 5. 実装時に決めること

- 全角文字を最終カラムに書こうとしたとき、deferred wrap の扱いをどうするか。
  - 先に折り返すか。
  - `DECAWM` がリセットされている場合はどうするか。
- スペーサーや本体を片方だけ上書き・消去したとき、もう片方をどう扱うか。
  - 対象の操作は `ECH`、`EL`、`DCH`、`ICH` など。
- 表示幅の判定に何を使うか。
  - レンダラーは `unicode-width` を使っている。
  - VT 側も同じ判定にしないと、2 のずれが別の形で残る。
